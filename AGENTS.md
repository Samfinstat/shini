# Правила работы с отчётом

## Назначение

Пользователь поручил сохранять текущий отчёт и последующие согласованные обновления в репозитории `Samfinstat/shini` (https://github.com/Samfinstat/shini). Репозиторий публичный: размещать только зашифрованные отчёты и общие инструкции; не загружать исходные Excel и незашифрованные данные клиента.

- arshini.ru и его региональные поддомены: SEO и контекстная реклама.
- «Еврошина»: SEO, без активных рекламных кампаний. Точный домен ещё не предоставлен.
- Привязка исходных выгрузок подтверждена пользователем: файл Метрики с префиксом «Еврошина» относится к SEO-сайту, без префикса — к arshini.ru.

## Обновление

1. Прочитать актуальный `index.html` и новые исходные данные.
2. Сохранить оба существующих доступа и шифрование. Не помещать пароли, ключи шифрования и расшифрованный внутренний разбор в исходный код, README, коммиты или логи.
3. Не переносить сведения из примеров других клиентов.
4. Общие KPI Директа брать из строки «Итого»; детализацию сверять отдельно. Расхождения указывать явно, а не исправлять без основания.
5. Не приравнивать конверсии Директа, достижения целей Метрики, уникальные заявки и продажи.
6. Отсутствующие позиции SEO, доход CRM, сведения о выполненных работах и поисковые запросы не выдумывать.
7. Сохранять исходный срез в `reports/2026-10-07/index.html`. Полные месяцы сравнивать с полными, промежуточные периоды — с сопоставимыми интервалами.
8. Проверять изменённую функциональность: входы, отсутствие внутреннего разбора в клиентском режиме, сохранение правок; при изменении макета — мобильное отображение и печать.
9. Для нового периода сохранить архив в `reports/YYYY-MM-DD/index.html` и обновить корневой `index.html`. Исправления в рамках текущего периода сохранять коммитами; первоначальный срез не перезаписывать.
10. Синхронизировать изменения с GitHub и сообщать результат и ссылку только после успешной записи. Само наличие файлов в репозитории не означает, что веб-отчёт опубликован.

Числа и внутренние комментарии находятся внутри зашифрованного HTML. Для обработки новых данных использовать предоставленные пользователем выгрузки. Если нужны отсутствующие данные или действующий пароль, запросить их; не заменять доступ новым без указания пользователя.
